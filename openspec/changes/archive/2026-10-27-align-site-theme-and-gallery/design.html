Context

See proposal.md for the outcome. The site currently uses actual released Telescope 0.1.1, with no local source override. site/gallery.json defines 12 examples across nine families and 40 unique supplied artifacts. Existing checks preserve 77 routes and 5,376 anchors. Main publishes to /diagrams.mbt/next/; historical release archives supply root and latest.

Goals and non-goals

Inherit the shared presentation and use real examples to verify it. Keep the site consumer thin. The change does not redesign diagram rendering or add a second gallery implementation.

Visual direction

The shared design uses Smithy indigo accents, cool gray surfaces, a family rail, preview cards and a large Preview/Source detail panel. The illustration below is the intended consumer layout. Production uses qualified SVGs and keeps the existing semantic scope labels.

Decisions

UI-1. Owner: align with Smithy

Use the shared Smithy palette on landing, documentation, API and gallery pages. Core light colors are #f9fafb, #ffffff, #111827 and indigo #4f46e5. Dark colors are #0f1014, #17181f, #e5e7eb and #a5b4fc. Keep diagram and standalone player artifact bytes unchanged.

DEP-1. Call: published toolkit only

Wait for Telescope publication and independent public-consumer reports. Then update apps/site/moon.mod, the exact release version and native archive SHA-256 pins in scripts/telescope.mbtx, related consumer assertions and installation docs. Use the published library and matching CLI from a fresh checkout. A local package or CSS override would repeat the duplication the extraction removed.

GAL-1. Call: retain the qualified content set

Keep the manifest version, IDs, source files, SVGs, players and current URLs. Let Telescope render family cards and source panels. Ensure filtering can distinguish implemented examples without changing their stated scope. Existing family anchors and gallery backlinks remain useful. The detail page keeps the separate player link and unchanged BPMN illustration and external trace-evidence wording.

TEST-1. Call: verify the real consumer

Extend apps/site/scripts/browser-test.ts and the existing strict gallery checks where they exercise observable behavior. Check landing/docs/API/gallery colors, card previews, text and family filters, result counts, reset, source tabs and copy fallback. Check themes, keyboard, no scripting and viewport widths 360, 768 and 1440. Do not duplicate Telescope unit tests in diagrams.mbt.

VER-1. Call: keep version roles

Deploy the new main site under /next/. Assemble existing release archives unchanged. Check canonical links, source links and base paths after assembly. This presentation change does not authorize a diagrams library release.

Verification

Run mise run format, mise run check, strict OpenSpec validation and the documented site consumer, compatibility, browser and assembly checks. Verify all 40 gallery artifacts byte-for-byte, all 12 stable detail pages and existing route/anchor contracts. Run a fresh checkout outside Telescope workspaces with no sibling dependencies. Retain historical assembly checks and UI-free library dependency checks. After authorized merge, verify deployed provenance, representative page types, gallery examples and downloads.
