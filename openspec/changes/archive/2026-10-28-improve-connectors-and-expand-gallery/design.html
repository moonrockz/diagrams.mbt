Context

See proposal.md for the problem and scope. The swimlane router also serves flowcharts. It reserves 12 px outside the endpoint outline. The BPMN router uses different offsets by side, including a 2 px bottom offset. Architecture reserves 16 px plus a small parallel-edge offset. These offsets are not one marker-aware clearance rule.

Graph painters and scene bindings build their path strings separately. Railroads already have some intrinsic curved geometry. The shared renderer has per-kind limits but no connector-style options. The published gallery has 15 cards in ten families; the development gallery has more corpus cases, including 38 sequence inputs. More published examples can reuse qualified inputs.

Goals and non-goals

Use one immutable final path for drawing, checking and motion. Keep model identity and source route points separate from presentation. Keep source parsing, workflow meaning and the public layout types stable. Add final path inspection without removing existing route-point access.

Do not add a general graph-layout service, a source-language style grammar, a whole legacy renderer or a new library UI dependency.

Decisions

CON-1. Owner: clear crossings by default

The owner requests more space near arrowheads, default curved crossing hops, selectable curved lines and more gallery examples. A crossing remains a drawing feature. It never creates a junction or a route between unrelated edges.

The owner confirmed the Bridge hop example during visual review: a small rounded arch carries one line over the other, with a clear underpass. This confirms the bridge's appearance. The numeric radius and the supplied-BPMN default remain author choices in CON-2 and CON-5.

CON-2. Call: typed renderer options

Add immutable connector options to SvgRenderer. Carry those options through public convenience calls that construct a renderer. Use an optional style with Elbow, Rounded and Curved alternatives. An omitted style uses the current kind's natural path form. Thus graph routes remain elbows by default and railroad loops keep their natural form. Crossing mode defaults to Bridge, with Plain as an explicit choice.

Provide a minimum terminal length and bounded corner/bridge radii. Start with 24 px minimum terminal length, 8 px corner radius and 5 px bridge radius. Derive the effective terminal reservation from the maximum of the caller's minimum and the marker/stroke/transition space. Treat these numbers as proposed author choices, to be checked by the first tracer. Reject negative or non-finite lengths and non-positive radii. Avoid string-valued options and implicit CSS. Include render options in automatic resource identity and retain explicit-prefix isolation for inline copies.

CON-2a. Owner: spread attachments and use clear sides

Spread multiple connections that land on one component side evenly across its usable extent. Keep one attachment centred. Reserve corner and marker padding instead of clustering several attachments near the side's centre. Retain stable fan ordering and actual outline attachment.

Automatic routing considers clear top and bottom approaches as well as left and right approaches. Use spare sides for return edges and congested bundles when that reduces clutter and keeps terminal corridors clear. Keep explicit authored ports and edge direction hints. Preserve supplied BPMN waypoints by default. Real junctions and grammar joins remain shared semantic points.

CON-3. Call: keep routing and final path geometry distinct

Add a pure connector geometry component under pkgs/diagrams-svg. Adapters map each kind's points and intrinsic path segments into a shared path value with move, line and curve commands. Preserve original route points for existing callers. Build the final path once and supply its serialization to the painter, scene bindings and configured trace overlays.

Automatic routers reserve terminal stubs before searching for the middle route. Smooth curves use bounded control points inside routing corridors. Rounded elbows replace local corners; smooth curves retain continuous internal tangents and are not only rounded right angles. Validate the resulting geometry against outlines and labels. A fixed elbow path remains a valid explicit style, not a silent fallback for a failed curved request.

CON-4. Call: classify crossings before adding bridges

Keep connector identity, semantic junction keys and paint order in the shared input. Detect transverse interior intersections on the styled paths. Exclude shared endpoints and semantic branch points, shared trunks, borders, lifelines and hidden layout constraints. Treat collinear overlaps as a routing issue. Use stable connection order to select the overpass.

Use bounded adaptive subdivision for curve intersection and clearance checks, with deterministic tolerances and numeric formatting on all four targets. Insert a local curved bridge and mask only the crossing underpass. Local scoped SVG masks avoid painting an opaque background patch over tinted groups or other content. These masks use generated definitions, not source markup. Keep dash and colour styles on the final path. Reduce bridge size within stroke-aware bounds or revise automatic routing when crossings are crowded; do not silently omit a bridge or intrude into labels, bends or terminal stubs.

A pure per-call work budget covers intersection candidates, subdivisions, crossings, path segments and output. A spatial candidate index can reduce dense pair checks, but it must not evade work accounting. Exhaustion returns a distinct connector limit diagnostic. Unsafe geometry returns a routing conflict.

CON-5. Call: preserve supplied BPMN paths by default

The current BPMN contract preserves supplied bounds, labels and edge waypoints apart from a common viewport translation. Proposed default: do not add bridges, curves or longer terminal approaches to supplied paths automatically. Add an explicit supplied-path styling option. When enabled, expose separate final presentation paths while retaining the exact source points. Do not move supplied shapes or silently repair a short supplied approach. Keep existing imported geometry findings. Unsafe requested styling returns a diagnostic.

This default is an author proposal, not an owner-approved exception. The pending owner question can change this default before implementation. It does not require a different shared-path architecture.

CON-6. Call: share path and crossing treatment with motion

AnimatedRenderer already accepts an SVG renderer. Use that route for connector settings. Replace independently reconstructed scene paths with final shared paths. Bind generated mask/clip references to their connections so progress, selection, trace highlights and moving tokens retain the underpass when appropriate. Avoid an overlay that draws an uninterrupted straight line through the bridge. Keep reverse traversal and repeated occurrences source-bound.

Static export is the direct styled canonical SVG, including its masks, with no viewer state. A download does not rebuild layout or change playback position. Graph queries keep their current semantic catalog. They do not use geometric intersections as edges.

Gallery coverage

GAL-1. Call: three additional sources per family

Use three additional distinct sources for each published family. Existing corpus cases can be promoted when they are readable and qualified; add source fixtures for gaps. Do not count colour variants, player variants or repeated trace views as additional sources. Retain all 15 existing IDs and routes.

Migration and verification

  1. Prove one automatically routed crossing flowchart from source to curved SVG, scene and offline playback. Include a tight marked approach and a plain-crossing comparison.
  2. Complete kind adapters and automatic terminal clearance. Preserve original public route-point access and document new additive option/path values.
  3. Complete crossing classification, masks and limits, then integrate all selection, trace and playback overlays.
  4. Review updated SVG/HTML snapshots. Confirm labels, source IDs, model values, query results, graph connectivity, frozen source corpora and existing URLs remain stable.
  5. Qualify all four targets, fresh consumers, browser motion, direct export, all gallery artifacts and root/next site compatibility. Reuse current mise tasks.
  6. Land as one pull request when practical. The final task-group pull request archives the change and fixes HTML asset links. Close beads after merge, then sync the tracker and remove the delivered branch and stale generated backups.

No release or publication is part of this change. Before merge, rollback is a normal branch revert. After merge, revert the coordinated renderer, snapshots and gallery updates together if a regression requires it; do not republish stale assets with incompatible scene paths.
