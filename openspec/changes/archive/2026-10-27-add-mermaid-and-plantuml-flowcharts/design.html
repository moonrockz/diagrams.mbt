Context

See proposal.md for the need and scope. The current Mermaid dispatcher accepts sequence, swimlane, ZenUML and architecture source. The swimlane parser already follows a frozen Mermaid 12.2.0 flowchart grammar. Its converter promotes top-level subgraphs to lanes, so accepting another header alone would give ordinary flowcharts the wrong ownership model.

The PlantUML envelope accepts regex, EBNF, JSON and YAML start markers. Activity syntax uses the shared @startuml envelope, which does not identify a UML family by itself. The existing root reader, body reader, printer and renderer accumulate bounded diagnostics and return no complete model on error. The shared renderer enum, animation catalog and SVG scene bindings each dispatch by diagram kind.

The source review covered pkgs/diagrams/render, pkgs/diagrams/animation/catalog.mbt, pkgs/diagrams-mermaid/dispatch.mbt, the swimlane parser/converter/model, pkgs/diagrams-plantuml/plantuml.mbt, its envelope, pkgs/diagrams-svg/scene.mbt, and the frozen swimlane corpus. Accepted requirements for swimlanes, PlantUML syntax, animation, SVG and gallery behavior supply the compatibility constraints.

Goals and non-goals

Owner: support Mermaid and PlantUML flowcharts with animation and the usual diagram feature set. This includes source APIs, portable models, standalone themed SVG, geometry checks, motion plans, route/reachability queries, offline controls, export and qualified examples.

Call: cover both modern and legacy PlantUML activity syntax. This is the proposed interpretation of the requested PlantUML support. Keep dialect-specific syntax and identity rules explicit while projecting both to one flowchart model.

Keep parsers separate from the shared model. Keep animation structural. Source-to-source translation, execution, external resources and upstream pixel matching are outside the design. See the proposal for the full exclusions.

Decisions

MODEL-1. Separate flowchart model, shared low-level helpers

Call: add pkgs/diagrams/flowchart and Diagram::Flowchart. Flowchart values own ordered nodes, edges, groups, explicit lanes, notes and structured control regions. Copy mutable collections at construction. Keep shape identity separate from typed control roles. PlantUML supplies explicit action/control roles; a Mermaid diamond remains a generic graph node unless explicit source data supplies a role. Regions retain branch order, loop membership and fork/join descriptions without imposing execution behavior.

Reuse existing text, marker and shape helpers where possible. Do not expose the swimlane model as the flowchart API or construct fake lanes to get its layout. A generic graph refactor of every existing family would enlarge migration risk. Extract small internal helpers only when the new path needs them and existing contracts can remain unchanged.

READ-1. Reuse Mermaid grammar without swimlane ownership

Call: add a typed flowchart dispatch variant and a flowchart conversion entry point in the existing Mermaid module. Parameterize shared lexical/statement handling by the expected header, and retain the header alias in the AST so canonical printing stays equivalent. Reuse the shared flowchart grammar and metadata handling. Normalize graph membership before applying the flowchart or swimlane ownership policy. Preserve the existing swimlane policy and all sequence-only entry points.

The alternative, changing swimlane-beta text to flowchart before reading, loses header locations and risks drift in diagnostics. Independent duplicated parsers would make grammar fixes diverge. Use small shared parsing helpers and distinct public result variants. Keep flowchart diagnostic codes distinct from swimlane codes. Flowchart local-direction behavior must match the flowchart reference, including any override caused by external connections.

READ-2. Activity envelope with explicit dialect

Call: extend the PlantUML envelope with an activity kind and typed dialect. A complete activity document retains its dialect; body-only reading receives it explicitly. Existing four-kind body calls retain their types and defaults. Classify the @startuml body from parsed activity statements, with comments, quoted text, multiline actions and notes excluded from header heuristics. A non-activity or ambiguous block receives an unsupported-kind finding. Reject unsupported mixed dialects explicitly.

Add activity syntax, printing and conversion subpackages within pkgs/diagrams-plantuml. Preserve the existing envelope's source reproduction, bounds, wrong-marker and multiple-block checks. Extending the current reader keeps one public dispatch surface and one diagnostic policy; a separate top-level activity module would duplicate those contracts.

FLOW-1. Build explicit control topology

Call: lower modern statements with a bounded control-stack and explicit pending continuation sets. If/elseif/else and switch introduce decision branches and merges. Loop frames hold entry, test, return and exit targets; break uses the nearest valid loop exit. Fork, merge and split retain distinct roles and branch membership. Final, kill and detach forms terminate or suppress continuation according to the pinned reference. Connectors and label/goto resolve through a bounded identity table. Unresolved or illegal references produce diagnostics.

Legacy conversion uses its own previous-activity and alias rules, named synchronization bars and explicit arrows. Do not merge modern action occurrences because their labels match. Generate IDs from deterministic occurrence paths with a reserved namespace and collision checking against authored IDs. Retain source bindings on introduced nodes, regions and connections. This gives scenarios a stable address for a branch or return edge without treating layout coordinates as identity.

SVG-1. Reuse vector primitives and expose flowchart geometry

Call: add a flowchart layout package under pkgs/diagrams-svg. Reuse existing measurement, path routing, palette and vector shape painting. Keep a separate layout result and checker for groups, explicit lanes, control regions, note placement and connection attachment. A private adapter to low-level geometry is acceptable; a public conversion to a swimlane model is not required.

Use deterministic cycle handling and feedback routes, distinct ports or routes for parallel edges, and declared order to break ties. Preserve group-local direction behavior from conversion. A collapsed group has display geometry at its boundary while catalog endpoints keep their authored identity. Unrenderable assets or failed layout checks return diagnostics and no SVG. Exact upstream coordinates are not a test oracle; use geometry checks and readable snapshots for this library's own layout. Crossing partition boundaries use measured container overlays over the primary lane hierarchy. Notes use private, unpainted placement containers or attachments to actual connection paths. Explicit arrow hints use bounded two-axis placement and routing ports; authored endpoints remain unchanged.

ANIM-1. Extend the shared catalog and player

Call: extend pkgs/diagrams/animation/catalog.mbt, SVG scene dispatch, node-binding variants and pkgs/diagrams-animated serialization. Bind edge occurrences to actual routed paths. Keep semantic endpoint identity separate from display attachment. Bind isolated actions as node visits. Exclude invisible constraints and note attachments from route topology.

Reuse direction-aware query and plan machinery. A default illustration visits an ordered finite set once. Explicit scenarios supply repetitions and concurrent groups. Guards and join specifications stay text; the player does not choose an executable branch or synchronize tokens. Hidden descendants return outside-view. Keep the canonical SVG separate from display overlays so download bytes equal a direct static render during any playback state. Reuse existing keyboard, reduced-motion, page-visibility, print and offline controls.

QUAL-1. Reference evidence comes from pinned upstream tools

Call: retain Mermaid 12.2.0 and PlantUML 1.2026.9. Freeze upstream source/documentation, licenses, digests, feature inventories and input fixtures. Mermaid graph expectations come from its pinned database. For PlantUML, use a test-only adapter over the pinned activity representation or independently inspectable generated connection metadata to record control topology and dialect identity. The first story must demonstrate extraction for a branch, loop and parallel region before the adapter is used as the full oracle. Do not derive expected topology with the MoonBit converter under test.

Extend the existing MoonBit task scripts, run through moonx and mise, for reference refresh/check and portable fixture embedding. Record any test-only Graphviz dependency required by legacy reference rendering with an exact version and provenance. Normal tests consume committed fixtures and need no Java, Graphviz, upstream JavaScript or network. Check upstream acceptance and topology for canonical output as well as original source. Documentation coverage cannot silently drop an example because the reference refuses it.

The inventory accounts for every pinned documented feature. Required control features cannot be reclassified as an unsupported subset during implementation. Keep native refusals, library execution/resource refusals and unapplied presentation separate. Preserve all presentation data for source printing; use the shared safe text/link policy in rendering. No runtime dependency or tool version upgrade is part of this change.

Primary references: Mermaid flowchart documentation, PlantUML modern activity syntax, and PlantUML legacy activity syntax. These are discovery links. Frozen version-bound files, rather than the moving web pages, define acceptance.

API-1. Add variants and document exhaustive-match migration

Call: add flowchart variants to the renderer, Mermaid parsed/tree dispatch and scene bindings, and activity variants to PlantUML document/kind types. Update every internal exhaustive match in the same story that adds a variant. Retain existing named APIs and their behavior. Add fresh model-only, reader and render/player consumer cases so accidental renderer or host-tool dependencies are caught. Document new match cases in module guides and the changelog. No release or publication is authorized by this plan.

Migration plan

Epic diagrams-bx7 and its eight dependent stories track the approved implementation. Deliver them in one pull request. The first story proves a thin source-to-player path for both formats, including both PlantUML dialects and reference topology extraction. Later stories complete the syntax profiles, layout, motion and example coverage without marking the feature complete early. Keep docs support descriptions aligned with landed coverage.

Land the last story with the archived change and merged accepted requirements. Update design asset links from ../../../.agents/templates/assets/ to ../../../../.agents/templates/assets/. After merge, close beads with the PR and merge SHA, close the finished epic and sync the tracker. Roll back a faulty story by reverting its code and corresponding capability claims together. No data migration is required.

Verification and delivery

Use independent parser/topology fixtures for compatibility, property-style read/print/read checks for typed edits, geometry checks for layout and browser qualification for offline interaction. Include malformed Unicode/CRLF, limits, unsafe metadata, collapsed scope, repeated labels, parallel edges, reverse routes and finite loop scenarios. Existing static bytes remain unchanged; shared HTML runtime changes need reviewed deterministic snapshots.

Run strict OpenSpec validation after planning edits. During implementation, run focused corpus and consumer checks, mise run format, mise run check, reference checks, SVG and animation browser checks, gallery qualification, and site build/link/smoke checks. Keep generated package interfaces with their implementation changes. The public libraries remain independent of the site and its UI packages.
