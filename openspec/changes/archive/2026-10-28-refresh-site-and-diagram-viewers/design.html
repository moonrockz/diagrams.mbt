Context

See the proposal for scope and the raster contract for supported inputs. The current site consumes published Telescope 0.2.1. Telescope owns gallery HTML, browser controls and site styles. The consumer supplies qualified source and preview artifacts. The local gallery comes from scripts/gallery.mbtx.

The standalone player is owned here by pkgs/diagrams-animated/html.mbt and assets/player.js and assets/player.css. Its CSS uses a different palette and a flat row of controls. It embeds all trusted assets. The text renderer returns String?; this is not a suitable container for encoded image bytes. No current module provides raster conversion.

The caller has selected A as the main logo and has confirmed that raster conversion covers SVG generated by diagrams.mbt. General third-party SVG is outside this change.

Goals and non-goals

Use one behavior and styling contract for gallery viewports and the shared player. Keep source, layout, playback state and downloaded canonical SVG independent of viewport state. Offer a real portable library conversion path that the download controls can call.

Keep UI code at the existing site and HTML renderer boundaries. Add no UI package or UI framework dependency to the published libraries. Do not replace the site's toolkit with a local HTML engine. Do not change playback semantics or historical release files.

Presentation

The landing page uses the A badge beside a short introduction and clear primary links. The saved simplified icon supplies header and favicon sizes. Diagram family cards use checked previews and retain existing anchors. B and C stay in the brand archive.

The player gives most space to the diagram. A compact header identifies the diagram family and its descriptive scope. The stage has fixed corner viewport tools. A primary Play/Pause action, Restart, Step and speed control sit beside the timeline and readable elapsed/total time. Exploration is grouped below the stage; export options are a separate labelled panel.

This arrangement is a design sketch. The final controls use accessible buttons, labels and native range input behavior. Icons supplement accessible names.

Decisions

UI-1. Owner: shared inspection actions

Provide top-right Fullscreen, Zoom in, Zoom out and Fit controls, pointer pan and keyboard pan. A stage wrapper holds the transform; the toolbar does not move. Use pointer capture, a drag threshold and pointer-cancel handling. Controls and form fields never start a pan. Do not capture ordinary page scrolling. Keep each viewer's state separate. Scale ranges from 25 to 800 percent of the fitted view. Fit and resize can recover the complete drawing.

Use native fullscreen when available. On rejection, use an accessible modal expanded view. Restore focus and document scrolling on exit. Preserve inherited theme values in that view. Do not use a separate SVG tab as the fullscreen action.

UI-2. Call: state and presentation stay separate

Preserve existing data-control and motion-data contracts. Add layout wrappers and public styling classes without moving motion state into the view. Transform the whole SVG and its overlays together. Printing removes transforms and controls. A skin change must not alter the canonical export or query graph.

The shell uses the site's light palette, background #f9fafb, surface #ffffff, ink #111827, accent #4f46e5; and dark palette, background #0f1014, surface #17181f, ink #e5e7eb, accent #a5b4fc. An explicit viewer theme wins over the site's stored site-theme, then the system setting. Blocked storage is harmless. Fixed SVG colors stay fixed. Do not reuse a site's theme switch to rewrite diagram source.

STY-1. Owner: public styling contract

Use scoped, stable hooks listed below in gallery and player controls. Inherit site tokens where they are present, with standalone defaults. Do not make consumers override private descendant structure or use high-specificity rules. Preserve per-instance overrides when entering fullscreen. Document values, defaults, inheritance and supported parts with a working custom-skin example.

RAS-1. Owner: first-class binary export

Add an optional portable pkgs/diagrams-raster library and register it in the workspace and version validation. Its API accepts generated SVG or a generated scene plus a source-bound playback plan. It returns a typed binary result with bytes, media type, dimensions and diagnostics. Do not put binary data into the existing text Rendered.output. Use typed PNG, JPEG and GIF options. Keep file writing in host adapters.

Conversion resolves the emitted SVG profile, including styles, explicit light/dark theme, paths, text, icons, clip paths and masks. Supply font data explicitly with a documented, licensed default font profile. Do not rely on host font discovery or network fonts. Diagnose missing required glyphs and unsupported generated features instead of silently omitting them.

The completed qualification spike selects published Milky2018/svg@0.6.0 for software rendering, Milky2018/css@0.6.0 and Milky2018/xml@0.6.1 for syntax support, mizchi/font@0.7.4 for explicit glyph outlines, mizchi/image@0.4.3 with mizchi/zlib@0.4.10 for PNG, and walkzzz/image@0.5.0 for multi-frame GIF. JPEG uses a licensed first-party adaptation of the mizchi/image encoder with integer color conversion and a fixed-point DCT basis. Its original runtime cosine calculations produced different native bytes. The GIF wrapper supplies the requested loop extension instead of the encoder's fixed infinite-loop extension.

The generated-SVG profile retains all eleven implemented gallery families. It includes explicit and adaptive palette styles, text and tspan positioning, regular and bold font faces, paths and arrow markers, transformed shapes, linear and radial gradients, clip paths, connector masks and the emitted icon filter profile. Normalization resolves the selected light or dark palette and converts supplied font glyphs to paths. The emitted feFlood/feBlend icon mask is normalized to equivalent geometry. Other unsupported input and unavailable required glyphs produce diagnostics. This remains a generated-SVG contract, not general third-party SVG conversion.

The licensed default font profile uses Noto Sans Mono regular/bold and Noto Sans Symbols 2 fallback. Callers can supply explicit faces and fallbacks. Standalone browser artifacts carry subsets for their own labels, with font inputs passed to the same library path. No host font discovery or network font loading is used.

Retained spike evidence records exact archive checksums, versions, licenses and fourteen generated fixture digests. All forty-three outputs match byte for byte on wasm, wasm-gc, JavaScript and native. Independent image decoding checks PNG, JPEG and a two-frame GIF. Same-font browser comparisons cover text, icons, clipping, gradients, transforms and real crossing masks. No target or diagram family was removed. Production work remains explicit in task groups 2 and 3 for bounded APIs, diagnostics, fresh consumers and source-bound GIF sampling, and in groups 4 through 7 for browser adapters and complete integration qualification.

RAS-2. Call: logical frames, bounded work

Sample a finite export interval from the existing pure playback plan. Derive overlays at each logical sample using the same measured connection paths, including curves, masks and reversed traversal. Generate frames without playing or screen-capturing the live DOM. Finite plans default to their full duration; repeating illustrations default to one cycle. Expose interval, frame rate, dimensions and loop behavior. Preserve the final finite frame and deterministically quantize GIF delays to centiseconds. Document palette quantization and alpha limits.

Validate all options before allocation. Use overflow-safe budgets for dimensions, per-frame pixels, frame count, cumulative pixels and output bytes. Process frames in bounded order. The browser export job reports progress and supports cancellation; it does not own live playback. PNG retains requested alpha. JPEG composites onto the chosen opaque background and exposes quality. Still exports always use canonical SVG, including its configured static trace evidence. Animated GIF adds only the chosen plan's sampled overlays, never toolbars or viewport transforms.

PKG-1. Call: keep existing ownership boundaries

Telescope owns published gallery markup and browser controls. Extend it through a matching upstream change and adopt a published release through both library and verified CLI pins. This change does not authorize cutting a release. The consumer must continue to build without a sibling checkout. Keep the local gallery's trusted runtime embedded for offline use.

The HTML renderer owns its framework-free player controls and compiled raster export payload. The gallery and player use the same supported raster library API. Expose a browser-compatible adapter built from that library; supply the compiled payload as trusted local assets and embed what standalone HTML requires. Do not replace conversion with a UI-only canvas shortcut. The shared viewport styling contract applies at both existing ownership boundaries. Add no Telescope dependency to a diagram module and no new UI package.

Verification

  • Compile and test raster API consumers on wasm, wasm-gc, JavaScript and native. Compare bytes, decode files with independent decoders and check dimensions, alpha, readable labels, icons, masks and paths. GIF checks include frame count, delays, loop setting and sampled pixel changes.
  • Use the existing Playwright harnesses for gallery, standalone animation and local gallery. Check narrow, medium and wide viewports, both themes, no-script static use, touch and mouse pan, keyboard control, fullscreen success and denial, Fit, theme changes and two independent viewers.
  • Check export cancellation, limits and offline operation. Compare UI downloads to library results, and confirm source, canonical SVG, playback state and existing URLs do not change.
  • Regenerate trusted player embedding and review current HTML snapshots. Run animation, gallery, SVG and root/next consumer qualification, then format, strict OpenSpec validation and the full repository check. Validate published Telescope adoption in a fresh consumer.

Risks and trade-offs

RiskMitigation
Raster libraries omit generated SVG features or support fewer targets.Qualify actual fixtures first. Record and resolve gaps before adopting a dependency; keep the accepted full scope.
Raster text differs from browser font discovery.Use explicit licensed font inputs and measured geometry, with glyph diagnostics and visual qualification.
Large GIF exports consume excessive memory.Bound dimensions, frames, total work and bytes; process frames in order and allow cancellation.
Fullscreen loses inherited styles or focus.Keep viewer scope intact, test custom properties and restore focus on every exit path.
Pan steals a card click or mobile scroll.Keep toolbar outside links, use a drag threshold and limit gesture capture to the active viewport.
Extra embedded code exceeds HTML budgets.Account for the export payload in the existing output budget and test limit diagnostics.
Upstream release is not yet available.Prepare and validate the upstream change separately; wait for an approved published release before pinning production adoption.

Migration plan

After plan approval, create a beads epic and one story per task group. Start with the portable raster qualification spike. Then land raster APIs and GIF sampling with their acceptance suites, shared toolkit support, player controls and gallery/branding integration. Request owner approval only when an upstream release is concrete and ready. No workstation publication is permitted.

Existing SVG and source routes stay unchanged. Regenerate current player HTML through the checked pipeline. Preserve historical archives. Rollback can restore consumer pins and current player assets; the saved branding originals remain available.
