Context

See the proposal for motivation and approved planning scope. At source ec16910, Python 0.0.1 exposes Mermaid rendering and diagnostic-position conversion only. The portable bridge serializes the complete SVG into JSON; the C adapter holds the GIL through native work and Python decodes that JSON into dataclasses.

The complete existing visitor seam belongs to moonrockz/bpmn: DocumentTree, NodeRef, EventReader, Visitor, TreeCursor and DocumentGraph. These preserve all retained XML content, namespace identity, source order and immutable revision identity. Other diagram and parser models do not yet share this tree contract. This change uses BPMN as its first complete adapter and tests the generic core with a second independent tree fixture. It does not claim query coverage for every diagram family.

The accepted Python specification currently requires holding the GIL for each call. Its delta explicitly replaces that requirement. The pinned native runtime has process-global cycle-collector state and non-atomic reference-count operations. Releasing the GIL alone is not a thread-safety design.

Goals and non-goals

Goals: make query compilation and execution first-class MoonBit APIs; preserve semantics in Python; reduce callback and conversion costs; allow unrelated Python threads to progress during native work. Every exported Python domain operation maps to a public MoonBit operation.

Non-goals: full Tree-sitter syntax, a Tree-sitter runtime dependency, all diagram adapters, arbitrary Python query predicates, public model construction parity, simultaneous native runtime execution, subinterpreters or free-threaded wheels. The existing SVG function remains supported; this is not a broader rendering binding expansion.

Decisions

API-1. Owner: one public portable query core

Add pkgs/diagrams-query, proposed module name moonrockz/diagrams-query. Its root package imports core libraries only. Its public schema and adapter contract describe kinds, categories, fields, attributes, scalar values, ordered children and stable owner-qualified node keys. Its public compiler accepts text or a typed query representation and returns the same checked plan. Independent cursors execute an immutable plan over an immutable adapter view.

Place the BPMN adapter in the opt-in moonrockz/diagrams-query/bpmn package. It imports the independent BPMN module and the generic query package. Neither moonrockz/bpmn nor its reader-only consumers import the query module. Python imports the query core and adapter through its native host. No grammar, matching or namespace logic is reimplemented in Python. A new generic dependency from BPMN was rejected because it would break the existing core-only module contract.

Adapter schemas have a stable identifier and version, a published kind/category/field inventory, and explicit open extension namespaces. Plans are reusable across documents with the same schema. Extension names in explicitly bound open namespaces are valid even when absent from a particular document. Unknown reserved kinds/fields and unbound prefixes are compile failures. Schema compatibility depends on the declared contract, not a hash of the current document's contents.

QRY-1. Call: a documented Tree-sitter-style subset

Use the syntax and evaluation rules below as language version 1. Tree-sitter patterns provide familiar notation; they do not supply our grammar or semantic node schema. Matching occurs over existing domain containment, not lexer tokens or invented attribute nodes. A named-field pattern constrains an actual child field. Attribute predicates operate on real attributes. Exact kind and category selectors are distinct. Unsupported features fail explicitly rather than being silently ignored.

Alternatives considered were a Python-only selector DSL, importing Tree-sitter and emitting a synthetic parse tree, and a full XPath implementation. The shared typed plan avoids a second evaluator, preserves original model identity, and permits a smaller bounded implementation. Text queries and typed construction are equivalent public entry points; users do not need to write strings to use the feature.

QRY-2. Call: bounded matching with deterministic batches

Use an explicit heap-stack matcher. Candidate roots follow containment preorder. An unlabelled child pattern selects a direct child; sibling constraints select distinct children in increasing original positions, allowing intervening siblings. A field-labelled child additionally requires that field. Enumerate successful child assignments lexicographically. At each root, try source patterns in source order. Alternatives retain source order and duplicate successful matches; no implicit cross-pattern deduplication occurs.

Check compilation and execution work before allocation or advancement. Limits cover query source units, patterns, nesting, inspected nodes/edges, pending partial matches, capture count, result count and projected output units. Query cursor state retains cumulative budgets and pending matches between batches. Terminal states are Complete, Stopped or Failed(reason); a nonterminal batch is never evidence of completeness. Close is idempotent. In-progress match limits bound ambiguous child assignments, and work limits bound empty-result scans. No batch request resets a limit.

Projection is separate from matching. Return only requested fields, with source-qualified handles and typed scalar tags. Do not expand every path, attribute or child list eagerly. Materialize requested paths and fields under the output budget. A caller can request identity alone or useful fields together. A typed unknown-field failure differs from a missing value on a matched node.

BPM-1. Call: adapt existing document identity and field rules

The adapter keeps an owning DocumentTree and maps its nodes to query keys without copying the underlying document. It can build bounded metadata indices that retain the original NodeRef handles. It uses NodeRef.category, kind, fields, attributes, scalar, path and location. Do not synthesize defaults or source spans. Retain expanded namespace URIs; source XML prefixes are not identity. Invalid or incomplete documents remain inspectable when the existing tree builder succeeds.

A complete query searches the chosen subtree, including its root. Returned paths remain document-relative. Document, text, comments and PI nodes are queryable categories. Reference and connection elements remain ordinary contained nodes; their target IDs do not become child links. Graph lookup, reachability and routes stay explicit calls and accept captured handles directly.

API-2. Owner: parity is a checked public contract

The compatibility table below is the minimum complete surface. Publish exact final signatures and data mappings in the implementation PR and compare them against generated MoonBit interfaces. Language conventions can differ: tuples/enums/read-only arrays can map to immutable Python records and tagged outcomes; Python iterators can wrap event sources. Default values, predicate semantics, traversal order, pruning, source positions, optional values, integer widths and failure categories cannot differ.

Use a shared normalized fixture format with schema/language versions, original sources, namespace options, query text, controls, projections, limits and expected results. Normalization records full source/resource revision identity plus ordinal, never an address or local allocation counter. Preserve node roles and typed scalar tags. Query syntax positions use half-open UTF-16 offsets; BPMN locations retain their existing UTF-16 units and one-based lines/columns. Python provides the existing offset conversion helper.

FFI-1. Call: owned buffers and opaque registry handles

Version the private C boundary independently from public package and query-language versions. Use explicit-width status, lengths and scalar tags, dedicated UTF-8 buffers, and opaque generation-checked owner/cursor/plan tokens. Do not expose MoonBit struct layouts, mangled symbols or Python pointers to the portable engine. A C-owned result record contains scalar metadata and buffers copied out while native access is serialized. Python constructs its strings and immutable records after native ownership is released. Small diagnostic metadata may remain encoded during migration, but complete SVG, node snapshots and batches must not use a JSON round trip.

Keep the current render_svg, Rendered, diagnostic classes and Unicode behavior unchanged. Add document reading, inspection, query and traversal namespaces. Retained views pin their immutable document owner. Closing a cursor releases its traversal state, not independently retained nodes. Concurrent advancement of one mutable cursor fails with a documented busy result; separate cursors remain independent. Invalid or stale tokens are checked before dereference. Finalization follows the runtime lock policy and performs no Python callback.

A zero-copy borrowed-memory API was rejected for this change. It would add lifetime and allocator constraints before measuring the value. Owned buffers remove the largest JSON cost without making Python retain raw MoonBit memory.

GIL-1. Call: release the GIL and serialize runtime access

Python call, GIL held: validate arguments, retain owners, copy input
detach Python thread state
  acquire the native runtime mutex
  allocate native values; render, query or advance a cursor
  copy results into C-owned buffers; release temporary MoonBit values
  release the native runtime mutex
reattach Python thread state
construct Python values or invoke a user callback

The mutex covers initialization, allocation, reference counting, cycle collection, query and traversal registries, and runtime counters. Waiters detach before blocking. Release the mutex before reattaching to Python; never wait for the GIL while holding it. No Python C API, callback or finalizer runs in the detached region. Pin input and owner lifetimes before detaching. Use platform synchronization primitives compatible with the existing wheel targets and Python 3.12 Limited API; qualify initialization and thread handoff on each target.

The first task is a concrete synchronization tracer bullet: audit the pinned runtime's thread-affinity assumptions and allocator handoff, then execute serialized calls from different Python threads with instrumentation and sanitizers. If the runtime cannot safely move between threads even under serialization, a dedicated native owner thread is the fallback design, not concurrent entry. That fallback requires an explicit design update covering queue bounds, shutdown and callbacks before implementation continues. Do not silently retain the GIL and claim this requirement is met.

Protect mutable cursor busy state independently so a second caller cannot race its advancement. Queries may retain the mutex for an operation's bounded native work; batches provide natural release points but are not a promise of fair scheduling. Existing process-aborting MoonBit panics remain a documented limitation. Free-threaded declarations and subinterpreter support do not change in this proposal.

VIS-1. Call: Python drives resumable visits

Use the existing public EventReader/EventSource control model for Python visitor, walk, fold and reduction facades. Each native advancement returns an owned snapshot and a continuation. Resolve implemented Python handlers once per traversal. Apply enter, then the selected typed family handler only after Continue, then resume native advancement with the resulting control. Omitted Python methods keep their native default and cause no Python callback.

SkipChildren acts before the child enters and still yields the current node's leave. Stop and callback exceptions emit no later callbacks. Nested traversal owns a different continuation, so the callback can reenter rendering or query APIs without retaining an outer native stack frame or mutex. Python fold/reduce accumulators stay Python-owned; control and combination order must match public MoonBit functions. Use explicit stacks for bottom-up reduction and deep trees. Preserve pruned-reduce behavior, including empty child results for a skipped node and absent result on stop.

Observational event batches are a separate API. They can amortize native transitions when the caller does not need immediate per-node controls. Do not pre-expose descendants before an interactive visitor decides whether to skip them. Native query predicates are fixed portable operations, not Python callbacks. Vectorcall can reduce callback argument allocation, but it cannot remove the GIL or the user's Python computation.

Language version 1

The following is the proposed public dialect, not a claim of Tree-sitter compatibility. Identifiers use ASCII letters, digits, underscore and hyphen, starting with a letter or underscore. A qualified name is prefix.local. Capture names also permit dots after the first character. Strings use JSON string escapes and preserve Unicode values. Whitespace separates tokens; semicolon-to-end-of-line comments are allowed.

query     := rule+
rule      := captured | '(' captured predicate+ ')'
captured  := node capture*
node      := '(' selector part* ')' | '[' captured+ ']'
part      := captured | field ':' captured | '!' field
selector  := qualified-kind | 'category.' category | '_'
capture   := '@' capture-name
predicate := '(' predicate-name capture string* ')'

Compile field names and exact predicate arities, rather than accepting arbitrary string* operands at execution. Qualify BPMN kinds and child fields through supplied prefixes, for example bpmn.userTask and bpmn.flowElement:. Unqualified attribute strings denote attributes with no namespace; attribute strings such as vendor:flag use the explicit query namespace map, not source-prefix guessing. Reserved category selectors include activity, process, event, gateway, document, text, comment and processing-instruction as published by the adapter. Captures bind nodes, never a copied string pretending to be a node.

PredicateOperands after its nameRule
#has-attr?capture, attributeTrue only when the attribute is present.
#missing-attr?capture, attributeTrue only when the attribute is absent.
#attr-eq?, #attr-not-eq?capture, attribute, literalRequire presence, then compare the decoded value. Absent is false for both.
#attr-in?capture, attribute, one or more literalsRequire presence and membership by exact scalar string value.
#text-eq?capture, literalCompare an adapter-declared scalar text value; no implicit descendant-text concatenation. A node without scalar text does not match.

Predicates in a rule are conjunctive and run only after all their referenced captures bind. Captures are unique within each successful alternative; two differently named roles can refer to the same node. Compilation checks all alternatives and predicate operands. Capturing an alternative means capturing its selected branch root. Repeated pattern indices and alternative branches remain distinct results. Query version 1 has no quantifiers, adjacency anchors, regex, directives or host-defined predicate execution. Each unsupported construct gets a stable diagnostic.

; Capture user tasks with the exact decoded name "Approve".
((bpmn.userTask) @task
  (#attr-eq? @task "name" "Approve"))

; Capture direct user-task children of a process.
(bpmn.process
  bpmn.flowElement: (bpmn.userTask) @task) @process

; Either concrete task kind, independent of source namespace prefixes.
[ (bpmn.userTask) (bpmn.serviceTask) ] @task

; All activity categories, including those with no name attribute.
((category.activity) @activity
  (#missing-attr? @activity "name"))

The first example can also match a nested user task because all candidate roots are searched. The second requires a direct schema field and does not treat a grandchild as a direct flow element. Query syntax, typed constructors and normalized-plan examples become executable shared documentation fixtures during implementation.

Qualification

Create corpus fixtures for both source-backed and constructed trees. Compare the query and existing traversal oracle on wasm, wasm-gc, js and native, then compare every Python wheel against that same normalized contract. Include malformed BPMN, unknown and vendor content, namespace aliases, duplicate IDs, source-revision changes, absent values, CRLF/non-BMP locations, overlapping patterns, repeated capture roles, deep trees, every bound and partial-batch failure.

Check all visitor controls, no-op defaults, fold/reduce order, nested walks and render/query calls from callbacks, exceptions, owner lifetime, stale/closed tokens, same-cursor contention and independent cursors. Test GIL progress during controlled native computation and during mutex waits with synchronization barriers and bounded deadlines. Test actual cleanup under contention, repeated imports and native module state. A heartbeat that runs only before or after native work is insufficient evidence.

Benchmark native oracle, direct Python calls, no-op visitor, field-collecting visitor, pruning, substantive callbacks, selective queries, match-all queries and batch sizes 1/64/256. Use identical documents and equivalent work. Include small, medium and large source fixtures and constructed 10,000-depth trees. Record cold/warm latency distributions, throughput, callback/native entry counts, projected bytes, allocation growth, time with the GIL held and mutex wait. Distinguish measurements from instrumented builds and normal release latency. Set regression thresholds from repeatable measured baselines, not an invented speedup factor. A query must prove zero Python per-candidate callbacks, even when latency varies.

Reuse the existing MoonBit task, oracle, sanitizer and wheel harnesses. Add focused portable query/traversal consumer tests and require clean installed-wheel tests on the existing Linux x86_64/arm64, macOS arm64/x86_64 and Windows x86_64 matrix with Python 3.12 and 3.15. Run native-Zig qualification for native build integration. Update build checks only where the new tests need wiring; do not silently broaden supported platforms or ABI claims.

Risks and trade-offs

Risk or limitationMitigation
Consumers expect full Tree-sitter compatibility.Publish version 1 grammar and predicate meanings, reject unsupported syntax, and test all examples.
Generic traversal erases namespace, revision or scalar distinctions.Keep expanded names and typed tags; compare owned source/revision and full node roles in cross-language fixtures.
Queries over ambiguous child assignments become expensive.Explicit work, pending-match, depth, result and output budgets with truthful failed terminal states.
Runtime thread handoff is unsafe even with a mutex.Prove serialized thread handoff first on the pinned runtime; update the design explicitly if a single-owner worker is needed.
Python callbacks reenter, raise or retain views.Own snapshots/continuations; release the native lock before callbacks; stop cleanly and retain the required immutable owners.
Queries still return almost every node.Expose projections and batches, benchmark materialization separately and retain the visitor API for expressiveness.
Native execution is serialized and panics can abort the process.State these limits explicitly. GIL release improves Python progress; it does not claim multi-core native throughput or panic isolation.
Large compatibility surface grows accidentally.Use the checked map as the acceptance boundary; require a new proposal for other diagram adapters or full model/render/raster parity.

Migration plan

  1. After plan approval, create the epic and task-group stories. Prove the public MoonBit query to Python path and serialized GIL release before expanding the surface.
  2. Add the portable query module, BPMN adapter, shared fixtures and complete compatibility map without changing existing BPMN behavior.
  3. Add the versioned structured boundary and resumable Python traversal. Switch existing rendering internally after exact parity passes.
  4. Qualify all targets and candidate wheels. Archive the change in the final implementation PR; close and sync beads after merge.
  5. Prepare any module/Python version changes and publication only under separate owner approval. This proposal grants no release approval.

Prefer one coherent implementation PR if review remains practical; task groups are stories, not mandatory PR boundaries. If split, each PR must preserve the existing rendering and independent BPMN consumer contracts. Rollback leaves old published wheels intact and removes the new adapter/API adoption together; never load a plan or extension under an incompatible private ABI. No document migration is needed because trees are immutable and query plans are not a stable serialized wire format.
