Context

See the proposal for scope. The shared swimlane router chooses sides, allocates incident-edge fractions across each side, and projects those fractions onto the actual outline. Flowchart and state layout use this geometry. Automatic BPMN uses a separate router with similar fraction-based gateway attachment. Architecture ports are authored sides.

A read-only check of the committed gallery reproduced the symptom. In swimlane-review-light.svg, decision B has points at (152,354), (224,391), (152,428), (80,391). Two routes meet its sloping edges at (88,386.889) and (216,386.889), while another meets (224,391). Each off-point endpoint is approximately 9 SVG units from a point. The outline projection is correct; the candidate preference is too generic.

The site consumes published Telescope 0.4.0. Its gallery detail page has Preview/Source tabs; the index cards do not. The shared planner already receives declared source text, so index inspection can reuse that data rather than fetch or reconstruct it. The local gallery is generated by scripts/gallery.mbtx.

Goals and non-goals

Choose natural attachments before reserving terminal corridors and routing the middle path. Keep explicit source constraints authoritative and retain pure, bounded, portable geometry. Give readers source text in the gallery itself, with accessible controls and retained viewer state.

Do not infer syntax from pixels, edit diagrams, rewrite authored BPMN geometry, add ASCII rendering, change graph meaning or introduce a local fork of the shared site engine.

Decisions

ANC-1. Owner: prefer shape-specific anchors

Build automatic candidates from the actual outline and its attachment profile. Diamond and choice profiles offer their four points first. Straight-sided boxes offer centered usable side spans, with marker and corner padding. Rounded shapes offer cardinal approaches and appropriate perimeter locations. Other supported outlines use their real boundary and usable spans rather than a rectangle substituted for the painted shape. Recompute candidates from measured bounds, including non-square diamonds and large labels.

Do not force every edge onto a point. Multiple independent connections must not appear to merge into one junction. Prefer another feasible point or side before spreading near a crowded point. If authored constraints require one side or all points are unavailable, use clear, deterministically ordered fallback locations on the real outline.

ANC-2. Call: evaluate anchors with routes

Use a bounded candidate set and stable ordering. Evaluate source/target candidates together with a feasible middle route. Hard constraints come first: authored port/side/direction, containment, actual outline, label clearance, marker approach and collision rules. Rank feasible choices by a documented cost for direction agreement, natural anchor preference, terminal congestion, bends and normalized route length. Shape width/height and marker dimensions affect usable capacity and cost, so a wide shallow diamond is not treated as a square.

Reserve all selected terminal corridors before middle routes and label placement, as the current router already does. Keep incident-edge ordering by the remote endpoint's cross-axis position, then source identity for ties. Reuse bounded route search and existing work limits. Prefer the complete candidate route to post-render snapping: snapping an endpoint after routing can place the arrow inside a shape or destroy its reserved straight approach.

ANC-3. Call: keep diagram-family constraints

Use one pure attachment-policy helper in the existing SVG library, with thin adapters for the shared swimlane geometry and automatic BPMN geometry. Flowchart/state inheritance then uses the same policy. Preserve architecture's authored service/group sides; apply any spacing improvement only within those allowed spans. Keep sequence lifelines, railroad joins, data-row ports, declared junctions, state boundary points and supplied BPMN waypoints out of generic node snapping. Self-loops need two distinguishable terminal corridors.

Expose the chosen result through existing route/final-path geometry. Scene playback and raster exports must consume that same final geometry. Review connector-only snapshot changes and update the state SVG compatibility wording to allow those reviewed changes. Do not relax collision or marker checks to accept a new preferred anchor.

GAL-1. Owner: source text in the gallery

Provide Preview/Source inspection on each implemented index card. Source means the original declared Mermaid, PlantUML, BPMN XML or other text, not raw generated SVG or guessed ASCII. Reuse the shared detail-page source panel and source-text map, with per-card IDs and independent tab state. Multiple sources have labelled filename selection and individual downloads. Render text with the existing escaping and version-rewrite protection so the displayed text matches download bytes. Source is selectable even if clipboard access fails.

Keep original source in generated markup. With no script, show a static preview and an expandable source panel or explicit source link. Initialize real tabs only when their panels are available. Support arrow keys, Home/End and visible focus. Bound long lines to the source panel. Keep controls outside the transformed preview and navigation link.

Preserve the mounted viewer when switching tabs rather than rebuilding it. Returning to Preview restores zoom/pan and keeps Fit, fullscreen and export functional. Tab state is independent across cards and survives gallery filtering. Hidden source does not change the current title/family search contract.

GAL-2. Call: retain shared ownership and offline source

Telescope owns the published gallery planner and tab runtime. Prepare its matching upstream change under that repository's rules, then adopt an approved published library and CLI release. Do not patch generated site HTML or make a sibling checkout a production dependency. The local gallery owns its markup; give each example an explicit source association and reuse the same accessible interaction pattern. Fixed-theme variants share their source. For a model-only fixture with no authored textual input, show an honest unavailable-source message and the existing fixture reference rather than inventing syntax.

Retain the shared styling hooks of the gallery/viewer controls and document hooks for tab, panel and source actions. All added assets remain local; original source and artifact URLs stay unchanged. Historical release trees remain unchanged.

Verification

  • Turn the existing decision examples into focused geometry regressions, plus a minimized diamond in all four directions. Check actual points, terminal tangents, marker clearance and false joins, not just successful SVG output.
  • Cover non-square shapes, large labels, boxes, circles, rounded shapes, fan-in/out, reciprocal edges, parallel identities, self-loops, congestion, explicit sides and supplied BPMN geometry. Test all connector styles, budgets and equal output on all four MoonBit targets.
  • Qualify final SVG, playback overlays and PNG/GIF outputs against shared route geometry and review only the expected connector snapshot updates.
  • Use browser checks for card/detail/local tabs, exact source, multiple filenames, hostile source, clipboard denial, no script, offline use, 360/768/1440 widths, both themes, repeated tab switches, independent cards, filters and root/next links.
  • Run format, full repository checks and strict OpenSpec validation. Fresh site consumers must build from published toolkit artifacts.

Risks and trade-offs

RiskMitigation
Every edge snaps to the same attractive point.Account for incident-edge capacity and corridor conflicts; retain distinct identities and safe fallback anchors.
Anchor candidate search grows rapidly.Cap candidates and charge candidate, route and collision work to existing explicit budgets.
A point preference creates a poor long detour.Score the complete feasible route with direction, bends and normalized length rather than snapping endpoints in isolation.
Existing supplied geometry changes.Exclude authored ports and supplied waypoints from automatic relocation; compare original geometry bytes.
More source text increases gallery page size.Include declared inputs once per card and share across themes. Retain bounded source panels and existing artifact limits.
Repeated tab IDs or hidden-viewer resize loses state.Generate per-entry IDs, keep viewer instances mounted and test repeated hide/show with retained transforms.
Toolkit publication is required for adoption.Prepare a concrete upstream change and verification before requesting any separately required release approval.

Migration plan

After approval, create beads for the task groups. Implement and qualify attachment policy first, then the family adapters and reviewed connector outputs. Build gallery source tabs in the shared toolkit, adopt its published release, and update the local gallery. Existing source URLs and semantic models stay unchanged. Archive the final change in its last implementation pull request; close and sync beads after merge. Restore prior pins and reviewed snapshots to roll back.
