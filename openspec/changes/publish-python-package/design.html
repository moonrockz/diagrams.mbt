Context

The spike prove-python-native-binding links the archive that moon builds for the host. That archive contains precompiled host objects (mimalloc and simdutf), so it cannot serve other platforms. A probe compiled the generated ffi.c, five runtime files and the adapter with zig 0.17.0 for Linux, macOS and Windows. The Linux modules passed the tests in Docker, and the macOS x86_64 module passed under Rosetta. With a custom compiler, moon itself also builds dir.c, which fails for Linux targets (NAME_MAX), so moonrockz/zig-cross exec cannot build this archive.

PyPI has a pending trusted publisher for the project diagrams.mbt: repository moonrockz/diagrams.mbt, workflow release.yml, environment pypi.

Goals and non-goals

Goals: build all wheels on one Linux or macOS host, test each wheel on its own platform, and publish 0.0.1 with trusted publishing.

Non-goals: the items under "Out of Scope" in the proposal.

Decisions

PKG-1. Owner: names and an independent Python version

The owner chose the PyPI project diagrams.mbt and the version 0.0.1. The import package is diagrams_mbt (Call), because a dot is not valid in an import name. The Python version is independent of the shared MoonBit version. diagrams_mbt.__version__ is its only source.

XB-1. Call: compile C sources with zig directly

The task compiles ffi.c (C backend, release mode), runtime.c, env.c, utf.c, stdio.c, backtrace.c and the adapter with zig cc -target. It uses the system allocator and the scalar UTF-8 code of utf.c, so no precompiled host object is linked. Targets: x86_64-linux-gnu.2.17, aarch64-linux-gnu.2.17, aarch64-macos.11.0, x86_64-macos.11.0 and x86_64-windows-gnu. Windows needs -D_CRT_RAND_S, and links python3.lib and the Universal CRT.

Alternatives: zig-cross exec (fails on dir.c and also drops mimalloc), and one native runner per platform (more runners, and Windows would need MSVC). The MSVC target of zig needs Microsoft SDK headers, which zig does not include.

XB-2. Call: pinned headers from python-build-standalone

Each target uses the CPython 3.12.16 headers of python-build-standalone release 20261026 for that target. The task checks the SHA-256 digest from the release SHA256SUMS before it extracts the headers, and for Windows python3.lib.

WHL-1. Call: a dependency-free wheel builder

A small Python script writes each wheel with the standard library: METADATA 2.4 with License-Expression: Apache-2.0, WHEEL, RECORD and the license file. The task runs it with the pinned CPython. There is no source distribution.

CI-1. Call: build on Linux, test on native runners

The reusable workflow python-wheels.yml builds the wheels and the oracle on ubuntu-latest. A matrix installs each wheel with pip from the built files only and runs the tests on ubuntu-24.04, ubuntu-24.04-arm, macos-15, macos-15-intel and windows-2025 with CPython 3.12 and 3.15. Linux jobs also run auditwheel show. CI and Release call the same workflow.

REL-1. Call: a separate Python path in release.yml

The trusted publisher names release.yml, so the upload job must be in that file, not in the reusable workflow. A push to main that changes diagrams_mbt/__init__.py starts the workflow. The python-plan job releases when the run is on main and PyPI returns 404 for the version; a pull request is a dry run. The pypi job has environment: pypi and id-token: write and uses pypa/gh-action-pypi-publish. The MoonBit plan already skips a released version, so the MoonBit path does not change.

Risks and trade-offs

RiskMitigation
MoonBit supports only MSVC on Windows; the wheel uses the MinGW ABI.Test the wheel on a Windows runner with two CPython versions before publication.
The wheels are about two times slower than the mimalloc and simdutf build.State it in the README; compiling those libraries with zig is a follow-up.
A PyPI version cannot be uploaded again.Publish only after all wheel tests pass; 0.0.x marks an experimental API.
A MoonBit panic stops the Python process.Document it; the spike report keeps the details.
